# mcp-go-context

MCP server written in Go for local project analysis, conversation memory, and documentation lookup.

## When to Use

Use this skill when:
- Analyzing project structure, dependencies, or multi-ecosystem workspaces (Go, Node.js, Python)
- Storing and retrieving persistent memory (decisions, fixes, conventions)
- Fetching documentation via Context7 or local fallbacks
- Tracking technical decisions with metadata (reason, alternatives, type)
- Promoting high-value session memories to persistent storage
- Getting context from recently changed git files

## Available Tools

### analyze-project
Analyzes project structure, dependencies, and provides comprehensive context.
- `path` (optional): Project path to analyze (default: current directory)
- `depth` (optional): Analysis depth (default: 3)

### get-context
Retrieves relevant context for the current task based on files, dependencies, and conversation history.
- `query` (required): Context query or topic
- `files` (optional): Specific files to include in context
- `maxTokens` (optional): Maximum tokens to return (default: 10000)

### fetch-docs
Fetches documentation for libraries and dependencies via Context7 with local fallbacks.
- `library` (required): Library name to fetch docs for
- `version` (optional): Specific version
- `topic` (optional): Specific topic within the docs

### dependency-analysis
Analyzes project dependencies and suggests relevant documentation.
- `includeTransitive` (optional): Include transitive dependencies
- `onlyDirect` (optional): Only analyze direct dependencies
- `suggestDocs` (optional): Suggest documentation URLs for dependencies

### changed-files-context
Gets context from files changed in recent git commits.
- `path` (optional): Project path (default: current directory)
- `commitCount` (optional): Number of recent commits to analyze (default: 5)
- `maxFiles` (optional): Maximum number of files to include (default: 10)

### remember-conversation
Stores important context from the current conversation for future reference.
- `key` (required): Key to store the memory under
- `content` (required): Content to remember
- `tags` (optional): Tags for categorization

### save-decision
Records a technical decision with structured metadata for future reference.
- `key` (required): Unique identifier for this decision
- `content` (required): Description of the decision made
- `decisionType` (optional): Type: architecture, fix, approach, tech-debt, security, performance
- `reason` (optional): Why this decision was made
- `alternatives` (optional): Alternative approaches that were considered
- `tags` (optional): Additional tags

### get-decisions
Retrieves technical decisions, optionally filtered by type or keyword.
- `decisionType` (optional): Filter by decision type
- `keyword` (optional): Search keyword in decision content
- `limit` (optional): Maximum number of results (default: 10)

### promote-memory
Marks a memory as promoted (high-value) for persistent storage.
- `key` (required): Memory key to promote
- `confidence` (optional): Confidence level: low, medium, high (default: high)

### get-promoted-memories
Returns memories that have been promoted from session memory.
- `limit` (optional): Maximum number of results (default: 10)

### search-memory
Advanced search through conversation memory with ranking by relevance, recency, and usage.
- `query` (optional): Search query to match against memory content
- `tags` (optional): Filter by tags
- `project` (optional): Project slug, "*" for all, "unassigned" for legacy
- `limit` (optional): Maximum number of results (default: 10)

### suggest-promotions
Analyzes existing memories using multiple quality signals and returns the best candidates worth promoting to long-term storage.
- `limit` (optional): Maximum suggestions (default: 5)

## Memory Convergence Model

This server is designed to work alongside Claude Code's SessionMemory:

| SessionMemory (summary.md) | mcp-go-context (this server) |
|---------------------------|-------------------------------|
| Session-level compaction | Persistent, high-value memories |
| Transient context | Decisions, fixes, conventions |
| Auto-generated by Claude | Explicitly promoted by user |

**Promotion flow**: Use `save-decision` for important choices → `suggest-promotions` to discover candidates → `promote-memory` to preserve them long-term.

## Scope

**This server IS:**
- Technical context for the current project
- Decision tracking and continuity
- Local documentation lookup
- Multi-ecosystem project analysis

**This server is NOT:**
- A general-purpose memory system
- A replacement for SessionMemory
- A semantic search engine

For session summarization and compaction, use SessionMemory (Claude Code's built-in feature).
